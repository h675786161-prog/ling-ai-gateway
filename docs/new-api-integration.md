# New API 融合方案

状态：方案已核对；当前生产服务是已完整迁移的玲的自定义网关，尚未安装 New API。

Northflank 具备持续运行容器和私有数据库的条件。其 Sandbox 官方说明包含两项免费服务和一项免费数据库；目前使用一项网关服务和一项 PostgreSQL。第二项免费服务可用于独立验证 New API，实际内存使用与免费规格需要上线测量，不能由资源名推断稳定性。

优先复用 New API 的完整后台和前端，在控制台中增加玲的模型实测、归并审核和候选回复页面。原官方名称归并、每站实测、智能加发备用、多回复保存、中文错误解释继续由现有模块提供。原库在融合完成前继续保存配置，不能直接把两种数据库表互相覆盖。

New API 前端会调用配套的用户、渠道、令牌、模型、统计与登录接口，复制构建后的静态文件无法接管现有后台。应选定明确版本，再接入所需接口；身份和配额需要统一验证，保留原管理门禁与已签发应用密钥的兼容入口。原站的上游密钥不允许通过 New API 原生“查看密钥”等接口重新下发前端，需要在融合接口中继续脱敏。

数据库使用当前 PostgreSQL 的独立数据库或独立专用角色，不增加第二项数据库附加服务；单实例先使用内存缓存，不部署 Redis。不得使用没有持久化卷的 SQLite。New API 数据库账号只访问自身数据；现有网关表和其他网站不授权给它。

聊天入口继续以官方模型名称为准，并保留多条回复在 SillyTavern 的接收行为。Responses、Messages 等新协议需要按上游实际能力验证请求、工具调用、流式输出、取消与保存；安装 New API 不等于已经能用于 Codex。

上线前验证：同一入口登录、原应用密钥、两个界面的配置一致性、模型归并与刷新、实测对 RPM 的计数、429/5xx/超时切线、第二条回复的保存与读取、中文脱敏报错、长流式与内存峰值，以及数据库权限。全部通过后才让融合版本接管现有入口。

来源：[Northflank 官方价格与 Sandbox](https://northflank.com/pricing)、[New API 官方部署与扩展说明](https://github.com/QuantumNous/new-api/blob/main/README.zh_CN.md)、[New API 容器构建文件](https://github.com/QuantumNous/new-api/blob/main/Dockerfile)。复用源码时保留项目许可证、署名和原项目链接。
